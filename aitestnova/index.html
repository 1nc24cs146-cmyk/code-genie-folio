What it does

Unit tests, in one click

Click “Generate test” above a function in JavaScript/TypeScript, Python, Java, or Go. Tests open for review first — nothing is saved until you save it.

Tests from a comment

Select a comment or spec, and AITestNova turns your spec lines into test cases.

Multi-model generation

Try up to 3 Ollama or OpenAI-compatible models and keep the best-scoring output. Or use the built-in template mode — no model, no key needed.

Record & replay APIs

Send & Record saves a real request and response. Replay diffs status and body, mock mode replays without the live server, and normalisation ignores volatile fields like timestamps and ids.

Suites, stability & coverage

Run API suites in order, replay tests 5 times to catch flakes, and check coverage against a baseline you set. A local dashboard shows replays, coverage, and stability history — no cloud, no telemetry.

Download count, visible in the extension

Antigravity's own extension-details panel has no downloads row, so AITestNova shows its live Open VSX download count at the top of its own sidebar panel, and in its README. This page's counter above also reads Open VSX live.

CI & pull requests, locally

Generate a GitHub Actions workflow for your stack, commit a saved test file locally, and create a PR description file. Push is never automatic.

Install in Antigravity

  1. Open the Open VSX page for AITestNova and install it, or in Antigravity go to Extensions → … → Install from VSIX and choose the VSIX file.
  2. Reload, then click the AITestNova icon in the activity bar.
  3. Open a code file and click “AITestNova: Generate test” above a function, or use the Record & Replay tab.

Template mode needs no account, no API key, and no model. Ollama and OpenAI-compatible models are optional. An OpenAI key, if you set one, is stored in the OS keychain — never in a file.

What it does not do, honestly

No kernel/eBPF traffic capture, no TLS interception, and no database, queue, or gRPC traffic capture. AITestNova only records requests made through its own panel. No cloud PR agent, no auto-push, no cloud dashboard, and no live inline autocomplete — those need a separate server or binary.

Template tests are starting points, not proof. Review them, mock dependencies, and adjust assertions before committing.
